## DECISIONS — LOCKED. DO NOT RELITIGATE.

1. **As-is baseline.** The test measures the console as it exists today. Known-missing engine wires (Workflow Spec §4) are *expected failures* that establish the baseline — they are opportunities that fail, not exclusions, and not build items for this lane.
2. **Unit of work:** one assignment run end-to-end: routed lead → admin confirm → `trip_expert_advisors` row → workspace open → build actions → `draft → in_review → delivered`.
3. **Defect categories (fixed taxonomy):**
   - `ABSENCE` — absence-compared-to-absence (null===null auth, unset env, unmounted router, missing escape/guard)
   - `DEAD_PATH` — dead or no-op code paths (e.g., empty-body `saveMutation`)
   - `STATE_DIVERGENCE` — UI state ≠ backend state machine (e.g., 5-stage UI vs 3-stage server)
   - `ENGINE_UNWIRED` — built engine capability not invoked by the surface
   - `MONEY_INTEGRITY` — hardcoded rates, missing idempotency, TOCTOU, non-atomic money-path transitions, fee literals outside `fee_bands`
   - `AUTH_SCOPE` — access beyond assignment scope (incl. `getTripRole` platform-role bypass class)
4. **Severity weights:** `MONEY_INTEGRITY` and `AUTH_SCOPE` defects rank above all others in the fix backlog regardless of frequency.
5. **Pass standard:** behavioral proof only. "Compile-green," "renders correctly," and grep hits are explicitly NOT pass conditions. Every gate claim requires `file:line` evidence at the audited commit.
6. **Sigma framing:** DPMO is computed for structure and trend, not as a launch metric. The actionable output is the defect Pareto by category.
7. **Kyoto constraint** applies wherever submit gates are in scope.

## PROBLEM STATEMENT

The Expert Console (workspace at `/expert/workspace/:tripId` plus its surrounding surfaces) has a specified workflow (forward-only `workspaceStatus` machine), a set of feature endpoints, and a set of engine capabilities it is supposed to consume. Spec documents (EXPERT_WORKSPACE_SPEC, EXPERT_WORKFLOW_SPEC) identify six flagged defects and a full engine-disconnect table, all pinned to commit `68d588e` (2026-06-02). There is currently **no instrument** that (a) enumerates what "correct" means as testable assertions, (b) proves the instrument itself can detect defects, or (c) produces a ranked, category-coded defect list to drive improvement.

This lane builds that instrument. This brief covers only: verifying current ground truth (Phase 0) and authoring the assertion checklist (Phase 1).

**Code is ground truth over spec when they diverge — always.** Where the audit finds the spec stale, the checklist is written against code, and the divergence is logged.

## PHASE 1 — OPPORTUNITY CHECKLIST (DOCUMENT ONLY)

**Mode: authoring one spec document. No harness code. No test code. No fixtures. No fixes.**

### 1.1 Deliverable
`docs/testing/CONSOLE_SIGMA_CHECKLIST.md` — the complete, numbered assertion inventory. Every assertion has:
- **ID** (stable, e.g., `WF-03`, `FL-12`, `CX-05`)
- **Layer:** `WF` (workflow) / `FL` (feature logic) / `CX` (connectivity)
- **Assertion** — one testable behavioral statement with expected observable outcome
- **Defect category** (from the locked taxonomy) it detects when failing
- **Severity** (`critical` = MONEY_INTEGRITY / AUTH_SCOPE; `major`; `minor`)
- **Evidence standard** — what Phase 3 must capture to prove pass/fail (response body field, DB row state, log row, rendered element)
- **Expected baseline result** — `pass` / `fail (known: ENGINE_UNWIRED)` / `unknown`. Known-fail rows stay in the count; that is the as-is baseline decision.

### 1.2 Required coverage (minimums, not the ceiling)
- **WF:** every legal transition succeeds exactly once per run; every illegal transition (including backward, skip, and repeat-terminal) is rejected with the allowed-set error; UI stage display equals backend state at each step; terminal state is truly terminal.
- **FL:** one or more assertions per endpoint in the §7 table, asserting *outcome* not status code (e.g., add-item → item present in itinerary read AND commission query invalidated/refreshed; commission → resolves configured rate else 0.75, and specifically never 0.30; notes PATCH → round-trips on subsequent GET; identity masking default-on, toggle reveals; non-assigned expert → 403/404 on every endpoint; Kyoto submit gate where in scope).
- **CX:** one binary assertion per engine wire from the Phase 0 matrix (invoked-and-rendered = pass), plus the "AI Gaps honesty" assertion (tab content matches what is actually computed).
- **Cross-cutting:** every `workspaceStatus` transition on a money-adjacent path asserts an append-only log row in the same transaction *once such logging exists* — at baseline this is an expected-fail `ABSENCE` opportunity, counted, not omitted.

### 1.3 Sizing sanity check
Target 40–60 opportunities per run. If the count lands materially outside that range, stop and flag before finalizing — too few means coverage gaps; too many usually means assertions are compound and need splitting (one observable outcome per assertion).

Checklist reviewed and locked by Leon. The locked checklist is the sole requirements source for the Phase 2 (MSA) and Phase 3 (harness) briefs. Phase 2 does not begin under this brief.
