Map layer rules: unmet-demand circles bucket to neighborhood centroids (city_neighborhoods), never raster heat and never traveler coordinates — the B2 aggregation posture verbatim, now carrying a $ value instead of a search count. Tap on a circle opens that neighborhood's requested-windows list; each window deep-links to the availability editor — same closing action as the calendar ghost slot, so map (Performance) and calendar (station) are two views of ONE metric (one rollup read, L6). The Catalog map's B2 overlay is untouched and does not gain the $ layer — one home per figure. The "Requested services" toggle (off above) lights up when Q5b confirms service_requests liveness — explicit asks pinned at their requested neighborhood where stated, city-bucket otherwise. Expert side: the same demand layer mounts as a 4th toggleable layer on the PlanCard map stack (pins / transport / expert notes / demand, expert role only) so experts see uncovered demand while building — feeding the AI advisor the same grain-labeled facts. Admin: the cross-market view in markets.tsx reuses the layer at city zoom, all markets, with per-market floor status.

Implementation notes for the dispatch: Calendar extends the existing kind-driven chip system in calendar.tsx — ghost is a new kind, not a parallel renderer. Catalog rows extend the existing .listing anatomy in services.tsx (funnel block mounts under .lmeta; removal badge joins .lright). Floors enforced server-side; the empty state above is what a suppressed cell looks like — the client never decides suppression. Mobile: calendar collapses to a week strip; the funnel bar and labels survive unchanged.
