What's already real vs. what this lane builds

The theme taxonomy is not new — every ready-made listing has declared one since the store launched, and the submit gate requires it. The gap is purely that nothing filters or groups by it yet.

Already exists

The theme field & vocabulary

ready_made_trips.plan_type — a closed 20-key list (hiking, romance & honeymoon, food & culture, photography, family, wellness, nightlife, cultural heritage, beach & island, festival, shopping, road trip, city, birthday, wedding, proposal, corporate retreat, custom…). Required at submit; changing it on an approved listing re-enters review. 100% of live listings carry one.

This lane

Server-side theme filter

GET /api/ready-made?planType=… — validated against the closed key list (unknown key → 400, never a silent empty page). The existing approved+active read-gate and ordering are untouched.

This lane

Theme-first layout

Chip rail (the Discover quick-category pattern, reused) + theme shelves replace the author-type sections. Author type demotes to a card badge; the author name links to their storefront when a handle exists.

This lane

Honest chips

Chips and shelves render only for themes with live stock, with real counts — never the full vocabulary as empty aisles, and never a guessed theme: only what builders declared.

This lane

Detail-page fix

The trip detail page still maps themes through a stale 9-entry table, so the 11 newer themes render as a generic label there. It switches to the shared vocabulary so the theme a builder picked is the theme a traveler sees.

Unchanged

Everything downstream

Buy → clone → refund loop, pricing modes, the Itinerary Templates section below the shelf, and the admin review queue are untouched. This is a browse-layer change.
