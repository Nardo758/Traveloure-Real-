Channels, not modes

v1's "store listing vs client trip" mode split becomes three channel cards with independent state on one build. The listing wraps the build when you ship to Store — not before.

Share card = the one PNG service

Social channel calls the existing share-image service with this build's real data — a build layout parameter, never a second renderer.

Caption AI moves server-side

One shared promo-text service (the provider engine imports it later). The current Content Studio saves nothing — this replaces it, attached to real content.

Client channel, honest v1

A build opened FROM an assignment is already attached. Attaching a free-standing draft to an assignment (copy items in) is the one new mechanism — scoped as its own step.

What this ratifies

Build-first, distribute-later

One "New build" entry; the client/store/social choice moves into the Distribute panel. Server change: a listing is created FROM an existing build ("ship to store"), instead of listing-then-trip.

the v2 model
Templates lane sunsets — seller side first

Retire the seller surface and block new listings now; consumer wind-down is its own decision-maker-read phase. Buyers keep purchased itineraries.

gated on prod counts
Content Studio → Distribute → Social

The studio page becomes a redirect; share card, caption AI, and Instagram publish live on the build they promote.
