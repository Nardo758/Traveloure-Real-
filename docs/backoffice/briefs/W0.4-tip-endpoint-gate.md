# W0.4 — Tip endpoint credits earnings with NO payment (interim gate)

**Tier:** Sonnet. **Migration:** none. **Money-path: YES — HUMAN READ before merge.** **Est.:** ~25k tokens.
Filed: FOLLOWUPS **L1**.

## Defect (verified)

`server/routes.ts:3419` `POST /api/expert/:expertId/tip` → `server/storage.ts:3298` `createExpertTip` records
the **client-sent amount** as a born-`held` `expert_earnings` row (type `tip`, storage.ts:3329) **plus** a
`tip_commission` `platform_revenue` row (storage.ts:3343) — with **NO Stripe charge anywhere in the flow**.
No money moves; an earning is credited from a request body. This is a §14/§15-class hazard.

It is **latent, not exploitable**: there are ZERO client consumers today (grep `client/src` for the tip POST
path / `api/expert/tips` / TipModal — no matches). So no UI reaches it. But the endpoint is live and the
money-endpoint guard misses it (no Stripe call in the handler for the guard to key on).

## Scope (interim gate — recommended by the map; do the smallest safe thing)

**Disable the write path until a real payment leg exists.** Make `POST /api/expert/:expertId/tip` return
`501 Not Implemented` (or `404`) with a clear message, and **do not call `createExpertTip`** — so no earning
or revenue row is ever written. Leave the read (`GET /api/expert/tips`, routes.ts:3457) intact (it just lists,
harmless). Add a code comment referencing this brief + FOLLOWUPS L1 explaining the endpoint is gated pending a
PaymentIntent+confirm leg (the coordination-fee §7 pattern is the template when it's built).

Do NOT build the payment leg here — that is a separate, scoped money-path brief. This brief only closes the
unpaid-credit hole.

## Traps

- Do NOT delete `createExpertTip` / the tip tables / `GET /api/expert/tips` — a future paid tip flow reuses
  them. Gate the *route*, not the storage layer.
- §14: confirm nothing else calls `createExpertTip` (grep) before gating — expected: only this route.
- Do NOT weaken the money-endpoint guard; if anything, this makes the guard's job easier.

## Gate

- Four standard gates.
- Behavioral: POSTing the tip endpoint returns the gated status and creates **zero** `expert_earnings` and
  **zero** `platform_revenue` rows (assert row counts unchanged — fails on the pre-fix code, which inserts both).
