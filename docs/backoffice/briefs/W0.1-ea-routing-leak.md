# W0.1 — EA routing leak: executive assistants boot into the expert console

**Tier:** Sonnet. **Migration:** none. **Server changes:** yes (small). **Est.:** ~45k tokens. Filed: FOLLOWUPS **M1**.

## Defect (verified)

`client/src/lib/role-utils.ts:1` — `EXPERT_ROLES` includes `"executive_assistant"`. Two consequences:
1. `getRoleHomePath` (role-utils.ts:7) returns `/expert/dashboard` for EAs because the `executive_assistant`
   → `/ea/dashboard` branch is caught by `EXPERT_ROLES` first — that branch is **unreachable dead code**, and
   `SignInModal.tsx:136` uses `getRoleHomePath`, so **every EA is redirected to `/expert/dashboard` on login**.
2. Every `requiredRole="expert"` `ProtectedRoute` (App.tsx — dashboard/services/templates/ready-made/
   content-studio/workspace/dmo-library) admits EAs via `userHasRequiredRole(role, "expert")` (role-utils.ts:14).

This contradicts the rest of the client, which already treats EA as **not** an expert:
`client/src/components/user-menu.tsx:26` (its own EXPERT_ROLES excludes EA — shows only "EA Console"), and
`client/src/contexts/ActiveConsoleContext.tsx:25` (maps `executive_assistant` → `"ea"`).

## Scope

1. **Remove `"executive_assistant"` from `EXPERT_ROLES` in `role-utils.ts`.** This makes the
   `getRoleHomePath` `/ea/dashboard` branch (line 7) live and excludes EAs from `requiredRole="expert"`
   routes — aligning role-utils with user-menu + ActiveConsoleContext (which already point this way).
2. **Dead code cleanup:** the unused `isEA` computed in `expert-sidebar.tsx:37` — leave it (harmless) OR
   remove it; do NOT add an isEA menu branch (EAs no longer render this sidebar). The `roleLabel`
   `executive_assistant` entry (expert-sidebar.tsx:89) can stay (harmless).
3. **The deliberate server-side DMO grant — DECISION, default = KEEP + FILE:** `expert-workspace.routes.ts:35`
   `requireExpert` names `executive_assistant` explicitly in its allow-list (an EA researching venues for an
   executive is a plausible DMO consumer — this looks intentional, unlike the client leak). **Default: keep the
   grant, and log a follow-up** that the EA console needs its own entry point into the DMO surface (otherwise
   it's a backend-without-a-surface, §9 inverse). Do NOT remove it unless CLAUDE.md or the decision-maker says
   the EA-DMO grant is unwanted.

## Traps

- Do NOT touch the EA console (`/ea/*`, `ea-sidebar.tsx`, `ea-layout.tsx`, `/api/ea` RBAC) — it is correct and
  separate; this brief only stops EAs from *leaking into the expert console*.
- `role-utils.ts` is imported widely — grep all callers of `EXPERT_ROLES` / `userHasRequiredRole` and confirm
  none rely on EA being an expert (expected: none, since user-menu + ActiveConsoleContext already exclude it).
- Do NOT change `EXPERT_ROLES` in `server/middleware/role-rbac.ts` unless a caller check shows an EA must be
  ejected server-side too — that is a wider change; if you find it necessary, STOP and report rather than expand.

## Gate

- Four standard gates (tsc delta 0, build, both guards).
- Behavioral: with a seeded `executive_assistant` user — `getRoleHomePath` returns `/ea/dashboard` (unit-level
  assert or a small script); an EA hitting a `requiredRole="expert"` route is redirected/denied, not admitted;
  an EA still reaches `/ea/dashboard`. Add the assertion so it fails on the pre-fix code.
