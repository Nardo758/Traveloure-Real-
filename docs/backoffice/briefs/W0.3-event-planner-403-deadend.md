# W0.3 — event_planner 403 dead-end on Store Listings

**Tier:** Haiku. **Migration:** none. **Server changes:** none (UI-only). **Est.:** ~15k tokens. Filed: FOLLOWUPS **M3**.

## Defect (verified)

`server/routes/ready-made.routes.ts:30` — `AUTHOR_ROLES = {local_expert, travel_expert, admin}`; **event_planner
is deliberately excluded** from ready-made authoring (403 at create, ready-made.routes.ts:56-58). But three
client surfaces lead an event_planner straight into that 403:
- `client/src/components/expert/expert-sidebar.tsx:65` — "Store Listings" nav entry is unconditional.
- `client/src/pages/expert/workspace.tsx:740` — the launchpad "Store Listings" card is unconditional.
- `client/src/pages/expert/ready-made.tsx:80` — the "New store listing" create button is ungated (an
  event_planner clicking it gets only a destructive 403 toast, onError line 64).

## Scope

Hide (or disable-with-explanation) all three surfaces when `user.role === "event_planner"`:
1. Sidebar entry (expert-sidebar.tsx) — omit the "Store Listings" item for event_planner (the sidebar already
   role-branches via `isEventPlanner`, expert-sidebar.tsx:37 — reuse it).
2. Launchpad card (workspace.tsx:740) — conditionally render.
3. Create button / page (ready-made.tsx) — hide the create CTA for event_planner; the page can show an honest
   empty-state pointing them at Itinerary Templates (their intended store lane).

Event planners KEEP: Itinerary Templates (their store lane), DMO Library, share tools. Only ready-made
authoring is removed for them.

## Traps

- Do NOT change the server gate (`AUTHOR_ROLES`) — the exclusion is intentional (decision-maker, 2026-07-25).
- Do NOT hide these for local_expert / travel_expert — they are authorized.
- Roles can switch via `PATCH /api/expert/role`, so compute visibility from the live `user.role` at render,
  not a cached value.
- This is superseded later by N2's full role tool-matrix, but is a cheap correct interim fix — keep it minimal.

## Gate

- Four standard gates.
- Behavioral (scripted or manual): as an `event_planner`, none of the three Store-Listings surfaces render/CTA;
  as a `local_expert`, all three still render. The event_planner never reaches the 403 toast via these paths.
