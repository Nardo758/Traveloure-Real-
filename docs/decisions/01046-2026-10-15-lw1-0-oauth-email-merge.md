NO schema, NO migration) | **R475 — LW-1-0: A FIRST-TIME SOCIAL SIGN-IN JOINS AN EXISTING ACCOUNT BY EMAIL ONLY ON AN EXPLICIT VERIFIED-EMAIL SIGNAL, NEVER AN ADMIN ACCOUNT, AND A REFUSAL CREATES NO SECOND ACCOUNT.** Decision-maker, Oct 15, 2026 (Launch hand-off "Answers" item 9, with overrides). Until now, a first-time Replit or Facebook sign-in whose email matched an existing account was merged into that account with no check that the provider had verified the email. On Facebook the session then carried the existing account's id, so whoever could make Facebook report an address could sign in as its owner, an admin included. ONE rule, `decideEmailMerge` (`server/replit_integrations/auth/email-merge.ts`, pure): a role in `EMAIL_MERGE_REFUSED_ROLES` (`admin`, the only staff role `users.role` carries) is refused first, whatever the signal; otherwise a merge needs the provider's verified-email signal, which for OIDC is `email_verified === true` exactly (`oidcEmailVerified`; absent, `false` or the string "true" are not a signal). Facebook's passport profile carries no such signal, so Facebook never merges; a Facebook identity's own `fb_…` account still signs in as itself, and it is now read BEFORE the email match. Whether Replit's OIDC claims carry `email_verified` could not be read from this session (its discovery document is blocked here), so the code takes the claim when present and otherwise refuses. A refused merge creates no account: the verify callback returns `EMAIL_SIGN_IN_REQUIRED`, both OAuth callbacks redirect that one code to `/login?error=email_sign_in_required` (Replit used to re-enter OIDC, which would loop on the same refusal), and the sign-in modal shows the one sentence in `shared/email-sign-in-required.ts`. Merges and refusals log user ids and the refusal reason, never the email. A verified Replit merge now really signs in as the existing account: the session is pinned to that account's id (`accountId`) on the first sign-in and on every token refresh. Before, it carried the Replit sub, which has no account, and every request answered 401. A merge no longer overwrites the existing account's profile image; the provider's image only fills a gap. **Behaviour delta, said out loud:** a person who earlier signed in with Facebook and was merged into an email account has no `fb_…` account, so Facebook sign-in now refuses them and tells them to use email and password.
