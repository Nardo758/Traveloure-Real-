The gate accepted a URL typed into the PR body: an assertion, not a verification, and a session could satisfy it by typing. Now, for each spec a PR wires into a workflow, the gate finds THAT workflow's runs on the PR head SHA through the Actions API (`actions: read`), waits for one to complete (bounded, `SPEC_ARMING_WAIT_MINUTES`, default 50), and passes only on `conclusion: success`. A run id named in the body is a POINTER the gate fetches and checks the same way (same repository, same workflow path, same head SHA, success) — never evidence by itself; the `spec-green:` marker is retired. No token ⇒ FAIL. **ARMED BUT SKIPPED IS NOT GREEN (decision-maker, same day: "read the Playwright JSON report and refuse an armed spec that was skipped").** A run concludes success when a spec skips itself, so for the green run the gate downloads its `playwright-json*` artifact(s) — `playwright.config.ts` now also writes `playwright-json/results.json` under CI — and requires at least one test of the spec, every one `expected` or `flaky`. A skipped test FAILS with the spec's own skip reason quoted ("ARMED BUT SKIPPED — … Reason given by the spec: …"); no artifact ⇒ FAIL ("cannot tell pass from skip"), so a workflow that arms a spec uploads `playwright-json/`.
