| 2026-09-27-occasion-backfill-tier-a | 2026-09-27 | [advisory] | **R136 — LD 42 D1 AMENDED: `trips.experience_type_id` IS BACKFILLED FROM EXACT EVIDENCE ONLY, TIER A ONLY, AND EVERY BACKFILLED ROW IS LOGGED (decision-maker, Sep 27, 2026).** A plan gets a backfilled occasion id only when **every** one of its `user_experiences` rows names the same `experience_type_id` (Tier A). **Tier B is rejected:** `trips.event_type` is not evidence, so `wedding`/`proposal`/`honeymoon` plans without unanimous events stay NULL, as does the pre-#1109 pen. Each backfilled row is written to an append-only `trip_occasion_backfill_log` (trip, id written, `evidence` jsonb naming the rule and the event ids, migration, `applied_at`, `reversed_at`), declared in `shared/schema.ts`, so any row can be reversed individually. The reversal clears the column only where it still holds the logged value, so a traveler's later choice is never undone. A NULL-occasion plan still gets a group where every occasion its `event_type` can mean shares one (`vacation` → Trips, `birthday` → Celebrations), without an occasion being claimed.
