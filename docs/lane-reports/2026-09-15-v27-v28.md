## V-27 — the Privacy Policy stops naming a data category the platform cannot hold

**Before.** `client/src/pages/privacy.tsx` listed, among the payment information Traveloure
COLLECTS, `Platform credit balances and usage` (`:78`), and among what it USES that data for,
`Manage platform credits and process payments` (`:138`). The credits/wallet system is RETIRED
(**LD 43(b)**): all four wallet/credit endpoints answer **410 Gone**
(`server/routes/payments.routes.ts:253,257,261,267`), and the docblock above them records that
`deductCredits` has no callers and `POST /api/wallet/add-credits` was a free-credits hole.

This is the **same** claim V-21 deleted from the Terms next door; it survived here because that
lane's scope was `terms.tsx`. Both documents are consent-of-record — `client/src/App.tsx:247`
redirects a signed-in user with no `privacyAcceptedAt` **or** no `termsAcceptedAt` to
`/accept-terms` — so this is §13 on the one page whose entire job is to be true.

**After.** Both list items are DELETED. No replacement sentence is owed: the platform does not
collect the thing, and a privacy policy does not owe a paragraph about an absent data category.
Nothing else in the file changed — in particular the card copy stays, because the retired product
is *platform credits* and not *credit cards*:

- `:72` "We do not directly store complete credit card numbers" — the Stripe clause.
- `:76` "Last four digits of credit/debit cards for display purposes" — a real display fact.

**The layer.** `client/src/lib/__tests__/terms-copy-honesty.test.ts` already carried the
retired-product predicate (T2) over `terms.tsx`. Rather than a second copy of that predicate in a
sibling file — the derivation-drift class §18 rule 1 names — the same rule now reads **both**
consent documents: the file set is a list, T2 iterates it, and T6's non-vacuity fixtures gained
the two sentences this lane removed, plus the reverse fixture (a credits claim written BESIDE card
copy must still be caught). Card copy is NEUTRALISED once — `credit card` and `credit/debit` are
blanked before the credit predicates run — rather than exempted by a lookahead on each rule, so
every rule reads plainly as "a remaining mention of credit is the product noun". A new T8 asserts
both card sentences and the surviving bullets of both sections, so the sweep can never be satisfied
by deleting a real fact.

**Stated negative space (§18d).** This is a source-text pin over TWO files. It says nothing about
the FAQ, `/pricing`, `/earn`, email templates, locale bundles or seed rows — the re-sweep swept
those and found nothing, but a credits claim written into a third page later is unchecked, not
exonerated. It also asserts nothing about the 410 rails themselves; it reads copy.

## V-28 — the reconciliation kind labels derive from the one vocabulary

**Before.** `KIND_LABELS` in `client/src/pages/admin/reconciliation.tsx` was a hand-written map
naming **ten** kinds. The job emits **seventeen** (`shared/schema.ts`
`RECONCILIATION_EXCEPTION_KINDS`, which its own comment calls "the canonical drift vocabulary").
Unlabelled: the six `rm_*` ready-made kinds (V-3's whole rail, ledger
`2026-09-12-readymade-reconciliation-rail`, plus D-18's `rm_delivery_not_announced`) and
`trip_booking_without_item` (D-11's). The render is `{KIND_LABELS[e.kind] ?? e.kind}` with the raw
kind already printed underneath, so an unlabelled row printed the identifier twice and the
sentence saying what drifted was simply absent — for the operator deciding whether money moved.

Nothing derived the map from the vocabulary, so it fell behind on every kind the job grew. Two
lanes added detection without adding a label; a third would have done the same.

**After.** The canonical list MOVES — unchanged, comments and all — out of `shared/schema.ts` into
a small dependency-free module, `shared/reconciliation-kinds.ts`, which `shared/schema.ts`
re-exports so every existing importer (`server/jobs/stripeReconciliation.ts`,
`server/__tests__/ready-made-announce-marker.test.ts`) is untouched. **The job is not changed.**
The move is what lets a client page read the vocabulary without pulling the ORM schema into the
browser bundle.

Beside the list, in the same module, `RECONCILIATION_KIND_LABELS` is typed
`Record<ReconciliationExceptionKind, string>` — so **tsc itself** fails the day a kind is added
without a label, which is the drift this row is about — and `reconciliationKindLabel(kind)` is the
ONE reader: it returns the label for a kind it knows and **the raw kind string** for one it does
not. §13 in the direction that matters here: an unknown kind is never given a guessed or
nearest-looking label, and never a generic "Unknown drift", which would be a claim about a fact
the client does not have. The page imports that helper and keeps its own map no longer.

**A THIRD copy the row did not name.** `server/services/email.service.ts` carried
`RECONCILIATION_LABELS`, whose own comment said it *"mirrors KIND_LABELS on the admin page"* — two
hand-maintained copies of one vocabulary, both seven kinds behind, and the digest email has no rail
column to soften an unlabelled row. It reads `reconciliationKindLabel` now. One wording moved with
it: the two legacy-rail kinds read `"Legacy: …"` rather than `"… (legacy rail)"`, which is the
admin page's phrasing, so the two surfaces now say the same sentence.

**The prototype hole, found by the pin.** The first draft of the reader was
`LABELS[kind] ?? kind`. `kind` arrives from an API response, so `toString` and `constructor` answered
out of `Object.prototype` and would have rendered a FUNCTION where a drift sentence belongs. K5 caught
it before the commit; the reader uses `hasOwnProperty`.

**The layer.** `client/src/lib/__tests__/reconciliation-kind-labels.test.ts` (pure; wired by the
whole-directory `unit-suite-client-lib` job) asserts: every declared kind has a non-empty label; no
label names a kind the vocabulary does not declare (both directions — the lists cannot drift); no
label is merely the identifier spelled back; an unknown kind falls back to the raw string; the
seven kinds this row names are present and labelled; and the page renders through the shared helper
rather than a local map.

**Stated negative space (§18d).** The test proves the LIST and the MAP agree and that the page
reads the helper. It does not prove the job emits exactly these kinds — the job assigns
`ReconciliationExceptionKind`-typed values, so tsc is that layer, not this test — and it makes no
claim about whether a label is the *best* wording, only that it exists, is not the identifier, and
was written from the kind's own docblock.
