## 1. The defect, restated from the row

`playwright/utils/auth.ts`'s `loginAs(page, email, password)` filled `/login`, clicked submit and
waited only for the URL to stop containing `/login`. It never checked that a session cookie was set
and never read `GET /api/auth/user`. **A login that did not happen returned normally**, and every
assertion downstream described the ANONYMOUS site while reading as authorization coverage.

A second helper of the same name — `playwright/tests/personas/_persona-helpers.ts:78`
`loginAs(request, email, password?)` — posted `/api/auth/login`, asserted a 200 and returned the
actor. Two helpers, one name, two contracts: the §18 rule 1 shape underneath the row, and the
reason the silent one survived as long as it did.

**Callers, counted on `origin/main`@`42e5213ef`** (`grep -rn loginAs playwright/ e2e/`): the row
names 29 calls in four suites — `seam-cross-console` (16), `phase-4-7-advanced-flows` (7),

## 2. What this lane changed

### 2.1 ONE `loginAs`, and it throws

`playwright/utils/auth.ts` is rewritten around one proof and one login rail:

* **`assertAuthenticatedSession(target, expectedEmail)` — THE ONE PROOF.** The jar carries the
  `connect.sid` cookie, `GET /api/auth/user` answers **200** through that same jar, and the user it
  names **is** the account asked for (email, case-insensitive). Anything else **throws**, with the
  evidence in the message (the cookie names actually present, the status, the principal actually
  found).
* **`loginAs(target, email, password)`** posts `/api/auth/login` through the caller's own cookie
  jar, then calls that proof. `target` is a `Page` **or** an `APIRequestContext` — `page.request`
  shares the browser context's jar, so proving the jar proves the page. It **returns the
  authenticated user**, so a caller can assert against the real principal instead of assuming one.
  Given a `Page` it leaves the browser signed in and on `/` (`domcontentloaded`), terms modal
  accepted if one appeared.
* **`logout(target)`** signs out and **proves the session is gone** (`GET /api/auth/user` → 401).

The header states what it proves and **what it does not** (§18d): it does not exercise the `/login`
FORM; it does not check role, entitlement or console access; it asserts the cookie by NAME; and it
reads `BASE_URL`, which it does not cross-check against Playwright's `baseURL`.

### 2.2 The persona helper is now a CALLER (§18 rule 1)

`_persona-helpers.ts`'s `loginAs` keeps its name, its persona-password default and its narrower
request-scoped type, and delegates the whole login-and-prove decision to the shared helper. There is
one implementation of "what proves a session exists" in the repository.

### 2.3 Two silent-pass helpers deleted (§18c)

`isLoggedIn()` (returned `false` on any error) and `waitForAuth()` (swallowed its own timeout with
the comment `// May already be logged in`) had **zero consumers** anywhere in `playwright/` or
`e2e/` and no state-bearing effect. Deleted rather than gated. `acceptTerms` is kept — it has an
internal consumer — and is now named for what it is: best-effort, asserting nothing.

### 2.4 A defect this lane found in its own first draft, and fixed before it shipped

The first draft of `logout` signed out through **`GET /api/logout`**. Measured against the local
production build: **404**, and `GET /api/auth/user` still **200** — the session survived. That route
is registered only inside `setupAuth`'s Replit-OIDC block. The canonical rail is
**`POST /api/auth/logout`** (`emailAuth.ts:530`), which `client/src/lib/__tests__/logout-endpoint-pin.test.ts`
already pins for the client. The helper now uses it and is held to the same pin; the endpoint choice
is written down in the header so it is not re-introduced.

chromium` cannot run here. The runs below used the image's pre-installed
`/opt/pw-browsers/chromium-1194` (Chromium 141) via `PLAYWRIGHT_BROWSERS_PATH`, against a
`playwright-core` that expects build 1208. **No repo file was changed to accommodate this.** It is
the reason this lane has no GitHub Actions run URL, and therefore why nothing was armed (§6).
