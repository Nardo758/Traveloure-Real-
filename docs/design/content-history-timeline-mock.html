Change types

Four badge styles, keyed off the row's changeType. An unknown type falls back to a plain outline badge — never a crash, never a mislabel.

created

First version. The row was registered. No diff is shown — there is no previous snapshot.

updated

Content edit. One or more fields changed; the changed keys are listed.

status change

Lifecycle move. e.g. draft → published. The underscore is rendered as a space.

moderation

Review action. Approve / reject / flag by a moderator.

Honesty rules

§13

No fake "no changes." The changed-keys line renders only when a real diff exists. A v1 created row shows no diff line at all — it never claims "no changes" for an event that legitimately has no previous.

§13

Real actor id only. "by …" appears only when changedBy is a real id. No placeholder, no "system" guess when the field is null.

L6

Reader only — zero new writes. No schema change, no write path. The data was already accumulating in content_versions; this dialog is the first consumer of the versions array the endpoint already returned.

state

Every state is drawn. Loading, error ("Couldn't load history"), and the empty case each have an explicit, honest render — the fetch only fires once the dialog opens for a real tracking number.
