01

The form as it is today

One shared component serves both experts and providers: a 4-step wizard titled What you offer → Details → Photos → Terms & requirements. Steps never validate — every asterisk is decorative until the final click — and Save Draft works from any step, which is genuinely good. Submitting, however, requires walking all four steps, because the submit button only exists on the last one.

02

The surfaces around it

Catalog (1,520 lines) is no longer "what I sell" — it hosts the storefront manager, a share/caption kit, a per-listing share dialog, two view toggles, a 30-tile category launcher, the map-authoring surface, a health scorer, the availability editor, and a promotion feed. Three of those sections' own copy says they belong on Distribute. Meanwhile Distribute — a full four-channel page — has no sidebar entry at all; it is reachable only through two buttons on other pages.

The provider Workstation is, in practice, a bundle-and-property manager with three link tiles on top. Its "Single service" rung doesn't host creation — it links away to the same ServiceForm as everything else. The ratified one door rule (ruling 74: "Add New Service → Workstation") appears in the ledger and the execution map, but no lane ever built it: five separate create links all bypass the Workstation and land directly on the form. And a first-time provider who did land on the Workstation would see two empty lists and a lock icon ("bundles unlock at 2 services").

03

Findings, ranked

Critical

The "Publish Service" button doesn't publish

Every provider create is clamped server-side to submitted for review — correct policy, wrong button. Experts get a card explaining the 48-hour review up front; providers find out only on the success screen after clicking "Publish." One role is told the rules before acting, the other after. The single largest honesty gap in the flow.

Critical

Price is asked before the service is described; the biggest branching decision is buried

Price sits in Step 1, before description, delivery method, or location. Delivery method — which gates the meeting-location card, the whole logistics card, the deliverable field, and the attestation set — is mid–Step 2, after pricing. The natural arc (what → where → when → price → publish) is scrambled.

Critical

Six answers to "where does this happen?", three different radius fields

Meeting Point, map pin, Service Area, Pickup Location, Drop-off Point — plus route stops on another page. Three radii ("Service Radius", "Pickup radius", "Won't travel beyond") live in two cards behind two different toggles; the surcharge help text sends the provider back up to flip a different switch to make the surcharge work. Transport is asked twice in two vocabularies on the same screen; duration twice in two formats; capacity three times across three steps.

Critical

Dead and inert controls shipped to sellers

A Published/Draft switch that is wired to nothing. Four logistics fields collected and read by no code — one of which nevertheless decides what UI the provider sees. Five "required" asterisks that never bind (price errors only surface after a server round-trip). The logistics card's own disclaimer ("these aren't shown to travelers yet") is wrong in both directions — several of its fields are live gates, four are inert.

Critical

Office-location pre-fill silently stamps non-place listings

The ruling-85 pre-fill seeds the pin and marks it "touched" with no delivery-method condition — so creating a PDF listing writes the provider's office coordinates onto a listing that has no location, with no UI showing it. Fix already dispatched — this one is a defect, not a design call, and is being corrected regardless.

High

The one-door rule was ratified but never built

Ruling 74 says "Add New Service → Workstation." The code has five create doors, none through the Workstation — and the Workstation isn't yet a place a first-time provider should land (empty lists, a locked rung). The ledger and the code disagree; nothing records a reversal.

High

Catalog is doing three pages' jobs; Distribute is invisible

The storefront header, the share-kit dialog, and the Promote block all have copy or duplicate mounts pointing at Distribute — which has no sidebar entry. The 30-tile category launcher (a creation surface) renders on Catalog's empty state. The map view now also hosts market-insights analytics.

High

Money configuration is scattered across three steps and mislabeled

Base price in Step 1; the travel-surcharge engine nested three levels deep in Step 2 — inside a card whose header claims its contents are inert (surcharge is live and charging); deposits in Step 4. A seller cannot see their money story in one place.

High

Role mismatches in both directions

Experts see vehicle-operator concepts (pickup, radius, surcharge, transport provision) whenever delivery method allows; providers see consultancy vocabulary ("Requirements from Client," "Revisions Included," "Includes Expert Notes"). Platform jargon leaks straight into labels: "Timezone (IANA)," "Content Affinity Tags," "Can this anchor a day?", and a literal URL path ("the /earn catalog") shown to sellers.

High

Seam hygiene: raw errors, unguarded delete, property rows leaking

Four Catalog card actions render raw JSON error blobs when a server gate refuses. Catalog's Delete fires with no confirmation while the Workstation's identical delete has one. Property and room rows render as ordinary Catalog cards whose Edit opens the wrong editor. No autosave anywhere on a ~78-control form — a refresh loses everything.

Worth keeping

What already works

Save Draft from any step (a PDF-guide draft is ~5 clicks — genuinely fast). Create and edit share one component. The never-clobber contract holds at the field level across all seven write surfaces. Conditional rendering already hides the logistics and location cards from non-place listings — the machinery for a branching form exists; it just runs from the wrong position.

04

The decision

Everything above sorts into three packages. They are independent — any subset can proceed — but this order is the recommended sequence: hygiene first, then the form, then the surfaces.

A

Fix pack — honest & cheap

No ruling conflicts · can start immediately
  • Rename "Publish Service" → "Submit for review", and tell providers about review before the click (the expert card already exists as the pattern).
  • Delete the dead Published/Draft switch; gate the four unread logistics fields behind an "Advanced" collapse or drop them until a consumer exists; fix the card's wrong disclaimer.
  • Make the asterisks bind — client-side enforcement for the five phantom-required fields.
  • Seam hygiene: friendly error messages on the four Catalog mutations, a delete confirmation, filter property/room rows out of the Catalog grid (or give them the right editor), bundle edit links that carry the bundle id.
  • Merge the duplicate questions: one transport question, one duration, one capacity story.
  • Office-pin silent write — already being fixed.

Every item is independently correct today; none changes the form's structure.

B

Form restructure — the redesign

Needs your ratification of the shape
  • Delivery method first. Ask it in Step 1, position 2, and branch the entire form off it — a PDF seller then never sees transport, pickup, surcharge, or meeting-location UI at all.
  • A basics fast path. Name, offering, delivery method, price, description → a saved, resumable draft in one screen (~90 seconds). Everything else becomes later steps or post-creation editing.
  • One location component. Collapse the six location questions into one map-first "where does this happen & how does the traveler get there," with one radius vocabulary.
  • Move advanced money out of creation. Surcharge and deposits become post-creation listing settings (edited from Catalog), leaving one price field in the create flow.
  • A publish checklist instead of a disabled button — "3 things left before review," each a deep link.

This is the Airbnb/Fiverr shape: short first pass → draft → enhance later. The conditional-rendering machinery already exists; this moves the branch point to the front.

C

Surface restructure — Catalog / Workstation / Distribute

Touches ratified rulings — needs explicit calls
  • Build the real one-door launcher — give the Workstation's first rung actual content (the 30-tile launcher moves there from Catalog's empty state) and route all five create links through it. This executes ruling 74 rather than conflicting with it.
  • Slim Catalog to read/manage/triage — move the storefront header, share dialog, and Promote block fully to Distribute. Clarifies ruling 74's "share tools stay on Catalog" — the duplicate mount already made it ambiguous.
  • Put Distribute in the sidebar. A four-channel page shouldn't be reachable only via two buried buttons.
  • Unify the two availability editors (Catalog gets ranged slots; one editor, both entry points). Additive to the C9 precedent.
  • Decide whether map authoring stays on Catalog (ruling 22b) or moves into the one listing editor — the only item that would need a true re-ratification.

Ends the "where do I change X?" fragmentation: Catalog to see and manage, Workstation to build, Distribute to promote, one editor to edit.

What I need from you
Package A — a go/no-go (recommended: go).  Package B — approve the five moves as the redesign direction; I'll mock the new flow before building, as we did for Catalog and Distribute.  Package C — pick which of the five surface moves to take now; the one-door launcher and the Distribute sidebar entry are the two with the highest return.
