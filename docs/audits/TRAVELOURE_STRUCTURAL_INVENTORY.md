# Traveloure Structural Inventory

## Module 1 / Section 1 — Page & Route Inventory

### Methodology and scope

- Ground truth is the current `<Switch>` in `client/src/App.tsx:348-1223`, with lazy imports resolved from `client/src/App.tsx:22-188`. Every named `<Route path=...>` declaration and the terminal pathless catch-all receives one row; no routes were inferred from links, server handlers, or registries.
- This section inventories route declarations only. It does **not** inventory sections, components, forms, fields, endpoints, or database tables.
- Coverage is conservative. A test is credited only when it programmatically navigates the declaration's route (directly or through a route-generated loop). Mere strings, links, static source assertions, API/security tests, or incidental matches are not coverage. `playwright/tests/app-routes.spec.ts:75-169` is a generated named-route sweep; it redirects unauthenticated protected routes before page content is checked. `playwright/tests/auth-routes.spec.ts:144-368` is a generated registry-driven authenticated smoke and provides only a heading/main/crash check, not feature-flow proof. Rows distinguish those minimal sweeps from feature-specific coverage.
- “Pages” below means distinct non-Redirect route component/file pairs, including App-local route components and NotFound; it does not mean source files under `pages/`. “Routes” means declarations, so aliases and the catch-all count separately.

### Access-semantics notes

- `ProtectedRoute` (`client/src/App.tsx:210-256`) requires a session, normally requires both terms and privacy acceptance, and optionally enforces a role. Unauthenticated requests save return-to state, open sign-in, and navigate to `/`. None of the current declarations sets `skipTermsCheck`.
- Role-family semantics come from `client/src/lib/role-utils.ts:5-20` and `shared/roles.ts:25-45`: expert accepts expert/local_expert/travel_expert/event_planner; provider accepts stored role service_provider; admin passes every required-role check; executive_assistant is its own family.
- A redirect row is itself unguarded unless it mounts ProtectedRoute; protection is applied only after arrival at a protected destination. Public dynamic token routes are not authorization claims; relevant pages/server APIs must validate tokens and ownership.
- Dev-only declarations mount their page only in development and redirect to `/` otherwise.
