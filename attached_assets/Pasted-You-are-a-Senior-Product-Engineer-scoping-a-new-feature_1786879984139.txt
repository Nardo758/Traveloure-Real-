You are a Senior Product Engineer scoping a new feature: 
report/block for the messaging system. Currently there is NO 
way for a user to report an abusive message or block another 
user — this is a real gap given cold-contact is unrestricted.

PROPOSE A MINIMAL VIABLE SCOPE (don't over-build):
1. Report: a user can flag a specific message or conversation, 
   with an optional reason. This creates a record admin can see 
   (ties into the existing admin panel — could reuse the review-
   moderation pattern already built for reviews).
2. Block: a user can block another user, which prevents the 
   blocked user from starting new conversations or sending 
   further messages to them (existing conversation history stays 
   visible to the blocker, just no new messages accepted).

IMPLEMENT:
1. DB schema for reports and blocks (reporter/blocker, target, 
   reason, timestamp, status)
2. API endpoints: report a message/conversation, block a user, 
   unblock a user
3. Enforce blocks server-side: a blocked user's send attempts 
   to the blocker must be rejected (403), not just hidden in UI
4. Minimal UI: a report button on messages, a block button on 
   a conversation/profile, and confirm both surface a clear 
   confirmation dialog before acting (these are consequential 
   actions)
5. Admin-side: reported content should appear somewhere admin 
   can review and act on (tie into existing moderation/ban tools 
   already verified in the admin panel)

TEST:
1. User A blocks User B — confirm B's future send attempts to 
   A are rejected server-side (test the API directly, not just UI)
2. Confirm B is NOT notified they've been blocked (avoid 
   escalating conflict)
3. User A reports a message — confirm it appears in an admin-
   visible queue
4. Confirm blocking doesn't delete/hide EXISTING conversation 
   history (audit trail matters)
5. Test that a blocked user cannot work around the block by 
   starting a NEW conversation with a different approach (e.g. 
   via a booking-adjacent contact path if one exists)

RESULT: one line — "report/block implemented and verified" or 
scope questions that need your input first.
