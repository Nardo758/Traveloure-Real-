Resolution waterfall

Every generated item runs through groundAiItems() — mutually exclusive rungs, first match wins, match threshold 0.82. Coordinates are copied from the matched entity only when the item has none of its own.

01

Catalog

Matched to a real provider_services row. Fully bookable in-platform — the item carries a live price and an add-to-trip action.

02

Affiliate

Matched to an affiliate_products row classified affiliate_bookable. Renders the agent-rail CTA — the traveler never leaves the platform, the affiliate URL never reaches the client.

03

DMO

Matched to a dmo_extracted_places row from the destination's official city guide. Sourced and named, not bookable.

04

Suggestion

No confident match on any rung. The item stays as an honest, unverified AI suggestion — labelled as such, offering no booking (§13).

Fail-closed rules

The CTA and the pill are self-guarding: the default state of every rung is "show less," never "show a dead action."

§16

The affiliate URL never leaves the server. The client holds only an opaque server-minted bookingToken. The CTA POSTs it to /api/affiliate-booking-requests; the booking agent resolves it back to the URL server-side. No window.open, ever.

§13

No token ⇒ no button. resolveAffiliateBooking() returns non-null only when bookingType === "affiliate_bookable" and a real token is present. Otherwise the CTA renders nothing — never a broken action.

§13

A miss is honest, not hidden. An unmatched item still appears — flagged "AI suggestion · unverified." Grounding failure downgrades the claim; it never drops the item or invents a listing.

auth

Signed-out taps open sign-in. The CTA calls openSignInModal() before firing, then confirms with a "Booking request sent" toast and locks to "Requested ✓".

Server contract

The affiliateBooking object on TripPlanActivity is present only when the item was really grounded to a bookable partner product — an absent key, not a null one, on every other item.
