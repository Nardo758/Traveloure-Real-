Add idempotency protection to Traveloure's 
checkout flow to prevent double-charging.

PROBLEM:
If a user double-clicks "Pay Now" or a network
retry fires twice, the same booking could be 
charged to Stripe twice with no protection.

TASK:

1. Generate an idempotency key on the FRONTEND
   when the checkout page loads (not on each click):

   client/src/pages/checkout.tsx (or equivalent):
   
   import { useState, useEffect } from "react";
   
   const [idempotencyKey] = useState(() => 
     crypto.randomUUID()
   );
   
   Include this key in every checkout API call
   for this session — even if user clicks 
   Pay Now multiple times, the key stays the same.

2. On the backend, in the checkout route 
   (routes/payments.ts), pass this key to Stripe:

   const paymentIntent = 
     await stripe.paymentIntents.create({
       amount: ...,
       currency: ...,
       // other fields
     }, {
       idempotencyKey: req.body.idempotencyKey
     });

   This tells Stripe: "if you already processed 
   this exact key, return the same result instead 
   of charging again."

3. Also add a DB-level guard:
   Before creating the booking, check if a booking
   already exists with this idempotencyKey:

   const existing = await db.select()
     .from(bookings)
     .where(eq(bookings.idempotencyKey, 
       req.body.idempotencyKey));
   
   if (existing.length > 0) {
     return res.json({
       success: true,
       booking: existing[0],
       note: "Booking already exists for this request"
     });
   }

4. Add idempotencyKey column to bookings table:
   idempotencyKey: text("idempotency_key").unique()

5. Test:
   - Submit a test checkout
   - Immediately submit the SAME checkout again
     with the same idempotencyKey
   - Confirm only ONE booking row is created
   - Confirm only ONE Stripe charge occurs

Do NOT change the checkout UI layout.
Do NOT touch vite.config.ts.
Show every file changed.
Report PASS/FAIL on the duplicate test.
