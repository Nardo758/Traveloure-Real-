### **FAILURE #3: e2e-selection-controls (run 27522323903, job 81342706080) — DOM Gate**

**Failing step:** "Apply database migrations"  
**Error class:** (a) DB bootstrap/seed/schema — fails before tests run  
**Database:** Local CI ephemeral Postgres (spun up at service in workflow; localhost:5432)  
**Exact error:** Migration `078_user_preferred_currency.sql` fails with **"column already exists"**

**Root cause:** Conflicting schema application paths in `selection-controls-gate.yml`:

1. **Line 82:** `npx drizzle-kit push --force`
   - Reads Drizzle schema from `shared/models/auth.ts`
   - Line 66 defines: `preferredCurrency: varchar("preferred_currency", { length: 3 }).default("USD")`
   - Drizzle pushes this directly to the CI DB — **column is created**

2. **Line 95:** `npx tsx scripts/verify-migration-ledger.ts` → triggers `runMigrations()` (server/index.ts:288)
   - Reads and applies all files in `server/migrations/migration-files.ts` (line 95: `078_user_preferred_currency.sql`)
   - Migration 078 contains: `ALTER TABLE users ADD COLUMN preferred_currency VARCHAR(3) DEFAULT 'USD';`
   - **Migration fails:** column already exists (Drizzle created it)
   - app never starts, so the downstream steps fail

**Evidence:**
- `shared/models/auth.ts:66`: `preferredCurrency` column is defined in Drizzle schema
- `server/migrations/078_user_preferred_currency.sql`: Migration tries to ADD the same column
- `server/migrations/migration-files.ts:95`: Migration 078 is registered in the canonical list
- `server/index.ts:288`: Server calls `runMigrations()` on startup; line 291 exits if it fails

**Why this matters:** The workflow's schema setup order causes a collision:
- `drizzle-kit push --force` applies the entire schema from Drizzle (which already includes `preferred_currency`)
- Then migrations try to apply again, causing a duplicate-column error

## GROUPED DIAGNOSIS

### **Shared Root Cause (Failures #3, #4):**

| Component | Issue | Evidence |
|-----------|-------|----------|
| Drizzle schema | `shared/models/auth.ts:66` defines `preferredCurrency` | Column definition in active schema |
| Migration 078 | Tries to ADD the same column via SQL | `server/migrations/078_user_preferred_currency.sql` |
| Workflow order | Drizzle push happens BEFORE migrations run | `selection-controls-gate.yml:82` then line 95 |
| Result | Duplicate-column error when migration executes | Server startup fails; HTTP checks fail |

**Why each workflow has its own DB setup:**
- `selection-controls-gate.yml`: Spins up its own Postgres container (line 59–66), uses `drizzle-kit push --force` (line 82), then runs migrations (line 95)
- `e2e-tests.yml`: Uses the DEPLOYED app's DB (line 55: `${{ secrets.DATABASE_URL }}`) — no local DB setup
- `e2e-deploy-smoke.yml`: Uses the DEPLOYED app's DB — no local DB setup

The fix to #3/#4 was **NOT applied to all workflows** — only the selection-controls-gate has drizzle-kit push, so it's the only one with the collision.

### **Separate Root Cause (Failures #1, #2):**

The deployed app is unreachable or failing to start because:

2. OR the deployment crashed and is unavailable
3. The e2e-tests workflow waits 5 min for the app to respond (line 36: 30 attempts × 10s sleep)
4. After timeout, the job fails before seeding or running tests

**Note:** Unlike #3/#4, which are CI-local DB failures caught immediately, #1/#2 are **deployment/availability failures** — the fix requires either:
- Deploying the latest code (with migrations) to the live app, OR
- Confirming the live DB has the column via direct inspection
