The failure is not the artifact upload. The real failure is that the e2e-selection-controls (DOM gate) job never got the app ready because PostgreSQL readiness checks are using the wrong database user.

Root cause
In the failing job logs, the server readiness step loops until timeout, while Postgres repeatedly reports:

Text
FATAL: role "root" does not exist
That means something in app startup is connecting to Postgres without using the workflow’s DATABASE_URL=postgresql://postgres:postgres@localhost:5432/traveloure, and is instead defaulting to the runner user (root). Because the app never finishes booting/seeding, /api/ready never returns ready, so the job exits here:

- name: Wait for server and seeding
  run: |
    for i in $(seq 1 60); do
      result=$(curl -s http://localhost:5000/api/ready || true)
      if echo "$result" | grep -q '"ready":true'; then
        echo "Server ready and seeding complete"; exit 0

What to check in code
Look for any startup/seeding/readiness DB connection path that:

ignores process.env.DATABASE_URL
constructs a local Postgres connection without explicit user/password
falls back to OS defaults like root
Most likely places:

DB client initialization
seed script invoked during startup
/api/ready handler
any module imported by server/index.ts
Likely fix
Make every DB connection path use the same explicit connection string, e.g.:

ts
const databaseUrl = process.env.DATABASE_URL;
if (!databaseUrl) throw new Error("DATABASE_URL is required");
and ensure no code does something like:

new Pool({})
psql / pg_isready / ORM config without user: 'postgres'
fallback to process.env.USER / local socket auth
Secondary improvement
To avoid the noisy artifact warning, make upload conditional on the report existing, or let the Playwright step generate it only after tests run. But that is not the blocker.
