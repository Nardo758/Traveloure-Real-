=== PLATFORM CONTEXT ===

Traveloure is the "Airbnb for travel expertise." Three parties:
- TRAVELERS: Book experts, generate AI itineraries, purchase 
  credits, join discount membership
- LOCAL EXPERTS: Get verified, receive routed leads, manage 
  bookings, earn payouts via Stripe Connect
- SERVICE PROVIDERS: Get verified (7-step), list services,

Current stack (already built on Replit):
- Frontend: React + Vite + TypeScript + Tailwind
- Backend: Node.js + Express (~18,500 line routes.ts)
- Database: PostgreSQL via Drizzle ORM
- Auth: Email/password + Replit OAuth + Facebook OAuth
- Payments: Stripe Connect + Stripe Identity + Stripe Treasury
- AI: Itinerary generation via /api/ai/generate-itinerary

=== SMART LEAD ROUTING ENGINE ===

Source: server/services/lead-routing.service.ts

POST /api/leads/route — score + auto-assign
GET  /api/leads/score-preview — dry run
GET  /api/admin/lead-routing-logs — audit
PATCH /api/admin/lead-routing-logs/:id/override — reassign

Scoring model (100 points, approved experts only):
- Destination match: 40pts (exact city=40, partial=25)
- Specialty match:   25pts (exact=25, partial=15, none=10)
- Availability:      20pts (20 - activeQueueDepth × 4, min 0)
- Response rate:     15pts ((responded/total 90d) × 15, 
                            default 0.5 if no history)

Failure modes to handle:
1. No approved experts → assignedExpertId: null
2. Top score = 0 (no destination match) → null assign
3. Thin markets at launch (e.g. Kyoto with few experts)

Logging: best-effort, swallows errors — under-counts in 
analytics (known gap)

=== KNOWN ARCHITECTURE GAPS TO SOLVE ===

GAP 1 — No funnel events table:
Currently requires stitching: users + trips + 
expert_requests + lead_routing_logs + bookings
Need: Single funnel_events table or event stream 
spanning T0→T7 for analytics

GAP 2 — Self-declared roles at signup:
role=userType written directly from request body at 
registration (emailAuth.ts:92) — no server-side gate
Risk: Inflated expert/provider counts
Fix needed: Supply metrics must filter on 
local_expert_forms.status=approved, not users.role

GAP 3 — Approved ≠ Payable:
Expert can be routing-eligible but Stripe Connect 
incomplete → can receive leads but not payouts
Need: Two separate flags tracked independently

GAP 4 — Dead-end qualified leads:
No fallback when null-assign occurs
Need: Queue, notification, or admin escalation path

GAP 5 — Legacy queue table:
expert_city_queues FIFO still exists in schema
Needs formal deprecation + migration plan

GAP 6 — Modal-gated top of funnel:
Landing CTA is openSignInModal() — no deep-linkable 
signup URL, limits paid acquisition attribution
Consider: /signup?ref= dedicated page

GAP 7 — Revenue dashboard was showing $0:
Now fixed — API returns real numbers + MoM growth % 
+ 10 recent transactions
Need: Confirm all 3 revenue surfaces report correctly

GAP 8 — Commission rate conflict:
Code: flat 30% on experience/cart checkout
Business plan: 75/25 expert split + 4-12% provider
Need: Architecture that correctly routes each 
booking type to the right commission calculation
