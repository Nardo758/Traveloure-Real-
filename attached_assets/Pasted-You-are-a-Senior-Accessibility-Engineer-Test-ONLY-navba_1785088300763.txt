You are a Senior Accessibility Engineer.
Test ONLY navbar accessibility on Traveloure
to WCAG 2.1 AA standard.

TEST 1 — Keyboard navigation only:
Do not use mouse at all.
Using only Tab, Shift+Tab, Enter, 
Space, Escape, Arrow keys:

Can you reach every navbar link? 
Can you open every dropdown?
Can you login/logout?
Can you open mobile menu?
Can you search?

Expected: Every navbar function 
reachable by keyboard alone.
Report any item that requires mouse.

TEST 2 — Focus visibility:
Tab through every navbar element.
Expected: Clear visible focus ring 
on every interactive element.
Not invisible focus (outline:none 
without replacement is a FAIL).

TEST 3 — ARIA labels:
Check every navbar button that has 
only an icon (no visible text):
- Hamburger menu button
- Search button
- Notification bell
- User avatar button
- Close button

Each must have either:
aria-label="descriptive text"
OR aria-labelledby pointing to visible text

Run: 
document.querySelectorAll('button')
  .forEach(b => console.log(
    b.textContent.trim() || 
    b.getAttribute('aria-label') || 
    'MISSING LABEL'
  ))

Report any "MISSING LABEL" results.

TEST 4 — Color contrast:
Check navbar text contrast ratios:
Normal text: minimum 4.5:1
Large text: minimum 3:1
Icons: minimum 3:1

Check:
- Navbar links (normal state)
- Navbar links (hover state)
- Active/current page link
- Dropdown menu items
- Search placeholder text

Use: chrome DevTools accessibility panel
or axe DevTools extension.

TEST 5 — Screen reader test:
With a screen reader (or axe extension):
Navigate the navbar.
Expected:
- Logo reads as "Traveloure home" or similar
- Nav landmark is announced as navigation
- Current page is announced 
  (aria-current="page")
- Dropdown state announced 
  (aria-expanded="true/false")
- Mobile menu state announced

TEST 6 — Skip navigation link:
At the very top of the page, 
is there a "Skip to main content" link?
Expected: Yes, visible on Tab focus,
jumps focus past navbar to main content.
This is required for keyboard users 
who don't want to tab through 
every navbar link on every page.

TEST 7 — Focus trap in mobile menu:
Open mobile menu on 375px.
Press Tab repeatedly.
Expected: Focus stays WITHIN the menu,
does not go to content behind overlay.
Press Escape: menu closes, 
focus returns to hamburger button.

TEST 8 — Motion/animation:
Does navbar have animations 
(slide-in menu, fade dropdowns)?
Check: @media (prefers-reduced-motion)
Expected: Animations disabled for users
who have reduced motion preference set.

TEST 9 — Touch target sizes:
On mobile, every tappable navbar element
must be minimum 44x44 pixels.
Check hamburger button size.
Check user avatar button size.
Check each dropdown item height.
Report anything under 44px.

TEST 10 — Error announcements:
In login form (reachable from navbar):
Submit with invalid data.
Expected: Error messages are announced
to screen readers via aria-live region
or role="alert".
Not just visual color change which
screen readers cannot detect.
