Ensure Stripe webhooks are never permanently lost 
if Traveloure's server is down when they fire.

CONTEXT:
Stripe automatically retries failed webhooks for 
up to 3 days, BUT only if your endpoint returns 
a non-200 status or times out. If your server is 
completely down (not just erroring), Stripe still 
queues retries — but you need to verify this is 
configured correctly and add a manual reconciliation 
fallback in case retries are exhausted.

TASK:

1. Confirm the webhook endpoint always returns 
   200 quickly, even if processing takes time:

   POST /api/stripe/webhook

   app.post("/api/stripe/webhook", 
     express.raw({type: "application/json"}),
     async (req, res) => {
       // Verify signature first
       let event;
       try {
         event = stripe.webhooks.constructEvent(
           req.body,
           req.headers["stripe-signature"],
           process.env.STRIPE_WEBHOOK_SECRET
         );
       } catch (err) {
         console.error(
           "[WEBHOOK] Signature verification failed", 
           err
         );
         return res.status(400).send(
           `Webhook Error: ${err.message}`
         );
       }

       // Acknowledge receipt IMMEDIATELY
       res.json({ received: true });

       // Process AFTER responding (don't block Stripe)
       processWebhookEvent(event).catch(err => {
         console.error(
           "[WEBHOOK PROCESSING ERROR]", 
           event.type, 
           err
         );
         // Log to admin_notifications so it's 
         // not silently lost
       });
     }
   );
