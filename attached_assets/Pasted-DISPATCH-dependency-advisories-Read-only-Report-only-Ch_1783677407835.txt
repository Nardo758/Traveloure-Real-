Do NOT click "Fix all with Agent". Do NOT run npm audit fix.
Do NOT bump any package. This lane produces a table and a recommendation.

Context: main is 14 commits ahead of origin/main and carries an unshipped
Lane 1 security fix plus unapproved eventsOnly commits. Adding a lockfile
diff to that trunk is not acceptable. Also: lockfile-purity is a required
status check.

1. GET THE PRIMARY EVIDENCE, not the panel's summary
   npm audit --json  (do NOT use --fix)
   For each of nodemailer 8.0.10, dompurify 3.4.10, esbuild 0.27.7:
     - the GHSA / CVE id
     - the actual vulnerability description
     - the vulnerable version range and the first patched version
     - severity per the advisory, and the CVSS vector
   The Replit panel is a summary. Advisory IDs are ground truth.
   If npm audit disagrees with the panel, report the disagreement.

2. DIRECT OR TRANSITIVE?
   For each: is it in package.json, or pulled in by something else?
     npm ls nodemailer && npm ls dompurify && npm ls esbuild
   Paste the dependency trees. A transitive dep cannot be bumped directly.

3. IS THE VULNERABLE CODE PATH REACHABLE HERE?
   This is the question the scanner cannot answer and the only one that
   determines severity FOR YOU.

   nodemailer  — do we call it at all? server/lib/email.ts is the
                 centralized email module and Resend is the transactional
                 provider. Grep for nodemailer imports. If nothing imports
                 it, it may be an unused transitive dep. Cite every import.

   dompurify   — where do we sanitize HTML, and is any of it rendering
                 user-supplied content? Expert notes, trip titles,
                 messages, and provider descriptions are all user input.
                 Cite every call site.

   esbuild     — is it a build-time dep only, or does it ship? Check
                 whether it appears under dependencies or devDependencies,
                 and whether the advisory concerns the dev server (in
                 which case it does not affect a built artifact).

   For each: REACHABLE / NOT REACHABLE / UNKNOWN, with file:line.
   "UNKNOWN" is a valid answer. Do not guess.

4. WHAT DOES THE FIX COST?
   For each, the minimum version that clears the advisory, and:
     - is it a patch, minor, or major bump?
     - breaking changes in the changelog between current and target?
     - does it move transitive deps? Show the lockfile delta size:
         npm install <pkg>@<target> --package-lock-only --dry-run
       (--dry-run and --package-lock-only ONLY. Do not write the lockfile.)

5. RECOMMENDATION
   One line per package: bump now / bump with Lane 1 / defer / remove
   entirely (if unused). Justify from steps 3 and 4, not from the
   severity badge.
