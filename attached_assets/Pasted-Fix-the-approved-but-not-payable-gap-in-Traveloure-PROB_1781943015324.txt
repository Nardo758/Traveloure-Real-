Fix the approved-but-not-payable gap in Traveloure.

PROBLEM:
An expert can complete their 6-step verification and 
be approved (local_expert_forms.status=approved) and 
therefore receive routed leads — but if they haven't 
completed Stripe Connect onboarding, they cannot 
receive payouts. Currently there is no UI or system 
tracking these as two separate states.

FIX REQUIRED:

1. In the local_expert_forms table schema 
   (shared/schema.ts), confirm these two fields exist
   as SEPARATE columns. If either is missing, add it:
   - identityVerificationStatus (already exists)
   - stripeConnectStatus: text, 
     values: "not_started"|"pending"|"complete"
     default: "not_started"

2. In the expert dashboard route handler:
   GET /api/expert/dashboard or equivalent
   Return BOTH statuses in the response:
   {
     approvalStatus: form.status,
     stripeConnectStatus: form.stripeConnectStatus,
     isRoutingEligible: form.status === "approved",
     isPayable: form.stripeConnectStatus === "complete"
   }

3. Add a status check in the lead routing service:
   In scoreExperts() around line 44 of 
   lead-routing.service.ts, the filter currently 
   checks status=approved only.
   
   Add a soft warning (NOT a hard block) when 
   routing to an expert whose stripeConnectStatus
   is not "complete":
   
   console.warn(
     `[PAYOUT WARNING] Expert ${expertId} is ` +
     `approved but Stripe Connect incomplete. ` +
     `Lead assigned but payout will fail.`
   );

4. Update the Stripe Connect webhook handler:
   POST /api/stripe/connect/webhook or equivalent
   When Stripe fires account.updated event and 
   charges_enabled = true:
   Update local_expert_forms.stripeConnectStatus 
   = "complete" for that expert

5. Add a new admin endpoint:
   GET /api/admin/experts/payout-gap
   Returns all experts where:
   status=approved AND stripeConnectStatus != complete
   These are experts who can receive leads 
   but cannot be paid.
   Response: [{expertId, name, email, destination, 
               approvalDate, stripeConnectStatus}]

6. Do NOT change:
   - The 6-step application flow
   - Existing Stripe Connect onboarding flow
   - The scoring model weights
   - Any approved expert's routing eligibility

Do not touch vite.config.ts or frontend files.
Do not install new packages.
Show every file and line changed.
