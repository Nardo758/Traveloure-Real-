Prevent double-booking of the same expert time

1. Add a database-level unique constraint as 
   the ultimate safety net:

In the bookings or expert_availability table,
add a unique constraint on:
(expertId, slotDate, slotTime)

This means the DATABASE itself will reject
a duplicate booking even if application code
has a race condition — this is the strongest
possible guarantee.

ALTER TABLE bookings 
ADD CONSTRAINT unique_expert_slot 
UNIQUE (expert_id, slot_date, slot_time);

2. In the booking creation route, wrap the 
   slot-check + insert in a transaction:

await db.transaction(async (tx) => {
  // Check availability INSIDE the transaction
  const existing = await tx.select()
    .from(bookings)
    .where(
      and(
        eq(bookings.expertId, expertId),
        eq(bookings.slotDate, slotDate),
        eq(bookings.slotTime, slotTime)
      )
    );

  if (existing.length > 0) {
    throw new Error("SLOT_ALREADY_BOOKED");
  }

  await tx.insert(bookings).values({
    expertId, slotDate, slotTime, ...
  });
});
